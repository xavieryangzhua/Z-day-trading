# Z-day-trading

简洁的本地 SPY 分钟级交易研究工具。只模拟买 Call，不下单，不接 LLM API。

## 启动

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m streamlit run app.py
```

打开 http://127.0.0.1:8510，或安装后双击 `Start.command`。

## 三个页面

- **想法**：买入想法和公共卖出方法分别新增、保存、编辑名称与 description。修改描述后自动设 `realize=false`；也可手动勾选重新实现。只改名称不使结果失效。
- **想法库**：一张表列出所有已实现和待实现的买入想法、卖出方法，只显示名称、类型和状态。直接让 Codex “实现并回测待处理想法”；不调用 API。
- **结果**：一次显示一个买入想法，对比公共卖出方法的平均单笔净收益率、胜率、交易次数。规则改动后不把旧结果当新结果展示。

## 文件与版本

`seed_ideas.json` 提供三个初始买入想法和五个公共卖出方法。首次运行生成 `storage/ideas.json`，这是你编辑的工作文件。`storage/research.sqlite3` 保存每次回测的想法版本、卖出规则版本、行情来源、SHA256、计算参数、代码快照、汇总和逐笔交易。旧记录不覆盖。备份整个 storage 目录即可保存想法和历史结果。

```sh
.venv/bin/python manage.py pending
.venv/bin/python manage.py run
.venv/bin/python -m pytest -q
```

Codex 阅读 description 后，通过 `manage.py implement ID '{"type":"breakout","indicator":"vwap","confirmation":"close"}'` 等命令登记相符的实现。超出现有规则的想法需扩展引擎；不会把未知描述自动套成既有模板。没有已实现的公共卖出规则时不提交部分比较。

## 入场与退出

突破条件：A（本根 open < 本根指标，close > 本根指标）或 B（前一根 close < 前一根指标，本根 close > 本根指标），任一成立。等于指标不算突破或站上。第二根收盘确认，第三根开盘买入。

三个买入想法：VWAP 收盘确认、EMA20 收盘确认、VWAP 开盘和收盘均在第二根 VWAP 上方。条件均在第二根收盘后确认，所以对开盘的比较也使用该根已完成指标。VWAP 按 HLC3×成交量计算，每天重置；EMA20 使用常规时段连续 K 线，跨日保留、最少预热20根；信号组合不跨日。

固定卖出为持有1/5/10/30分钟，对应分钟结束时用收盘价卖出；剩余交易时间不足则在当日收盘退出。连续两根阳线从入场所在 K 线开始计数，阳线要求 close > open，阴线或十字星清零；第二根阳线结束后下一根开盘卖出。未触发或已无下一根时当日最后一根收盘退出。

每个“买入想法＋卖出方法”独立模拟，不重叠持仓。退出所在 K 线不重新入场；固定收盘退出后可在下一根开盘入场，下一根开盘退出的策略需等退出这根之后再入场。不同卖出方法的持仓长度不同，所以有效入场样本可能不同。不隔夜。

## 收益

每笔买1张 Call：初始报价 $2/股，即 $200/张；Delta 0.5；报价每分钟减 $0.01，即每张减 $1；往返手续费 $2。

```
卖出报价 = max(0, 2 + 0.5 × (标的卖价 - 标的买价) - 0.01 × 实际持有分钟)
净损益 = (卖出报价 - 2) × 100 - 2
净收益率 = 净损益 / 200
```

显示平均单笔净收益率，不是累计账户收益率。无交易显示空值，不伪造零收益。固定 Delta 和时间损耗属于情景模拟，未使用真实期权报价、IV、Gamma、点差或滑点。归零后含手续费最多损失 $202。

## 行情来源

复用旧项目的 `SPY_1min_2025-01-02_2025-04-28.csv`，常规交易时段 79 天、30,810 根1分钟K线。来源和原始下载地址、固定源提交及SHA256见 `data/source.json`：第三方 SPY-Analysis 仓库中的 Databento XNAS.ITCH（Nasdaq 单一场所），不是全市场合并成交量。新项目使用独立 SQLite，不混入旧策略结果。

行情不提交 Git；在其他机器使用时需自行将同一 CSV 放入 data/。引擎核验文件哈希、OHLC、时间顺序和完整分钟；不补值，不把残缺交易日的最后一根冒充收盘。当前校验针对这份完整的正常长度交易日数据；未来加入半日市数据需同步扩展交易日历支持。
